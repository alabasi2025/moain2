# ADR-0009: تعدد المستأجرين من اليوم الأول

**الحالة:** مقبول

## السياق
النظام يُبنى لعميل واحد، لكن المشكلة عامة لكل مخبز متعدد الفروع. إضافة `tenant_id` لاحقاً = إعادة كتابة كل استعلام.

## القرار
`tenant_id` على كل جدول عملي. `TenantRepo` يحقنه. `tenant_id` من الجلسة فقط. اختبارات عزل في CI.

## البدائل المرفوضة
- **قاعدة لكل مستأجر**: D1 يدعمها، وقد ننتقل إليها لاحقاً لعميل كبير. لكن الإدارة والـ migrations أعقد للبداية.
- **بدون tenancy**: يُغلق باب المنتج.

## العواقب
- (+) تسجيل عميل جديد = صف واحد. منتج SaaS جاهز.
- (−) حرف إضافي في كل استعلام — Drizzle يُخفيه.
