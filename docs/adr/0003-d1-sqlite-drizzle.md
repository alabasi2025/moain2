# ADR-0003: Cloudflare D1 (SQLite) + Drizzle، مخطط قابل للنقل

**الحالة:** مقبول

## السياق
حجم البيانات لمخبز: 10 فروع × 150 صنفاً × 365 يوماً ≈ 550K سطر طلبية/سنة. المخزون: ~50 حركة/يوم. صغير جداً. نحتاج معاملات ذرّية وقيوداً حقيقية وTriggers.

## القرار
D1 كقاعدة أساسية. المخطط مكتوب بـ SQL قياسي (`02-domain/04-schema.sql`) مُختبَر على SQLite، مع ملاحظات نقل لـ Postgres. Drizzle ORM يُولِّد الأنواع ويدعم المحركين.

## البدائل المرفوضة
- **Supabase Postgres من البداية**: RLS مدمجة ميزة، لكن تكلفة أعلى، زمن استجابة أعلى من اليمن (منطقة واحدة)، وتعقيد لا يبرره الحجم. **نحتفظ به كخطة هجرة موثقة.**
- **Turso (libSQL)**: ممتاز لكن يضيف مزوداً ثانياً؛ D1 في نفس المنصة أبسط.
- **MongoDB/NoSQL**: الدفتر والقيود والـ triggers تحتاج SQL حقيقي.

## العواقب
- (+) معاملات ذرّية، Triggers للـ immutability، Time Travel 30 يوماً.
- (−) D1 10GB/قاعدة — بعيد جداً. لا `DECIMAL` حقيقي → REAL + تقريب في التطبيق + INTEGER للمال.
- (−) لا RLS → نفرض العزل في الكود + اختبارات (ADR-0009).
- عتبة الهجرة: > 50 مستأجراً نشطاً أو حاجة لتقارير تحليلية ثقيلة.
