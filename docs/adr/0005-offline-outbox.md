# ADR-0005: Offline-first بنمط Outbox، بدون CRDT

**الحالة:** مقبول

## السياق
الإنترنت في اليمن متقطع. الفرع يجب أن يُكمل طلبيته دائماً. iOS لا يدعم Background Sync.

## القرار
- Dexie (IndexedDB) لتخزين: الكتالوج، المسودات، صف Outbox.
- كل كتابة → Outbox (PENDING) → إرسال عند `online`/`visibilitychange`/كل 30s، FIFO صارم، exponential backoff، Web Locks.
- `client_uuid` على كل كيان → الخادم idempotent.
- 4xx = قرار نهائي يُعرض للمستخدم (CONFLICT)، لا إعادة محاولة.
- لا CRDT/LWW: تصميم النطاق يجعل كل كيان مملوكاً لطرف واحد.

## البدائل المرفوضة
- **PowerSync / ElectricSQL / Replicache**: مزامنة ثنائية الاتجاه كاملة — قوة زائدة وتعقيد وتكلفة لنطاق تعارضاته شبه معدومة.
- **Background Sync API**: غير مدعوم iOS.
- **بدون offline**: يخالف واقع المستخدم.

## العواقب
- (+) بساطة، شفافية للمستخدم (شارات واضحة)، لا تعارضات صامتة.
- (−) المزامنة تحتاج فتح التطبيق على iOS — مقبول للسيناريو.
- (−) قرارات الخادم (قفل/ترحيل/موافقة) غير متاحة offline — بالتصميم.
