## 1. فهمي للنظام (15 سطراً)

1. العميل طلب "شيتين إكسل"، لكن ما يصفه هو **نظام تشغيل يومي** لشركة مخابز فيها معمل مركزي يغذّي عدة فروع.
2. **الدورة الأولى (الطلب ← الإنتاج ← التسليم):** كل فرع يرسل من جواله طلبية واحدة لكل نافذة ويوم (أصناف مجمّعة بالتصنيف، +/−، ملاحظة)، ويستطيع التعديل حتى وقت الإغلاق.
3. عند الإغلاق، بتوقيت المستأجر لا UTC، تُقفل الطلبيات ويتجمّع **أمر إنتاج واحد** لكل (معمل، نافذة، تاريخ) على شكل مصفوفة: صنف × فرع × إجمالي.
4. المعمل يعيّن المسؤول والوقت المتوقع، ويطبع ثلاثة تخطيطات (مجمّع / حسب القسم / ورقة تجهيز لكل فرع). الطباعة تأخذ دائماً **آخر snapshot**، لا العرض الحي.
5. التسليم **حدث** غير قابل للتعديل (الكمية الفعلية + اسم المستلم + توقيع)، والجزئي مسموح. التعديل بعد الإغلاق يمر فقط عبر **استثناء** يوافق عليه مدير المعمل ويُستهلك مرة واحدة.
6. **الدورة الثانية (المخزون):** دفتر حركات **append-only** هو مصدر الحقيقة الوحيد. لا عمود كمية في المواد، والرصيد مشتق دائماً.
7. الإدخال يتم عبر **سندات** (توريد/صرف/تسوية/تحويل/هالك/مرتجع) بالمسار مسودة ← ترحيل ذرّي ← إلغاء بحركات عكسية فقط، مع **متوسط مرجّح متحرك** ومنع افتراضي للرصيد السالب.
8. تقرير "حالة المخزون" يعطي **الأعمدة الإحدى عشرة حرفياً** كما طلبها العميل لأي فترة، مشتقة من الدفتر، مع Excel وطباعة. الجرد يأخذ snapshot عند الفتح ويولّد حركات للفروقات فقط.
9. **المنصة:** تعدد مستأجرين من اليوم الأول (`tenant_id` من الجلسة فقط)، وسبعة أدوار مقيّدة بالموقع، ودخول بكلمة مرور مرة ثم PIN من جهاز موثوق، وسجل تدقيق append-only.
10. **المرونة بالتهيئة لا بالكود:** عدد الفروع والمعامل، شجرة التصنيفات، النوافذ وأوقاتها، الوحدات، العملة، المنطقة الزمنية، الأرقام، الشعار واللون — كلها من الواجهة (35 بنداً في مصفوفة المرونة).
11. **الشكل والسلوك:** PWA يبدو ويتصرف كتطبيق أصلي (تنقل سفلي حسب الدور، أهداف لمس 48، Sheets، Skeletons بدل الدوّار، حركة 150–300ms، مناطق آمنة، RTL من الجذر، وضع داكن) بهوية دافئة هادئة لا تشبه قوالب الذكاء الاصطناعي.
12. **Offline-first بنمط Outbox:** الإدخال من طرف واحد يعمل بلا إنترنت ويُزامَن بـ `client_uuid` متساوي الأثر. أما القرارات المشتركة (قفل، ترحيل، موافقة) فتحتاج اتصالاً عمداً.
13. **المكدس:** React 19 + Vite + Tailwind 4 + Radix + TanStack Query + Zustand + Dexie في الواجهة، وHono على Workers + D1 + Drizzle + KV + R2 في الخادم، وZod مشترك بينهما.
14. الطباعة HTML/CSS ← طباعة المتصفح (لا مكتبات PDF)، وExcel عبر ExcelJS بـ RTL وصيغ SUM حقيقية. القيمة للعميل تظهر في **M1**، ويوقف إكسل هناك.
15. **ترتيب البناء:** M0 أساس صلب مختبَر ← M1 الطلبيات والإنتاج والتسليم ← M2 المخزون ← M3 الوصفات والاحتياج. لا تُسلَّم نصف ميزة.
